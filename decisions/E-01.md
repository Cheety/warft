# E-01 — Base and image tool

**Status:** ruled · **Source:** panel E-01 of the architecture overview, revision 2 (`workpod-plattform-leitstand.html`), carried over per AP-0.1. Translated under [the language ruling](language.md); the identifiers are untouched.

## Ruling

mkosi on Fedora packages with the Fedora kernel. The root filesystem under dm-verity, A/B via `systemd-sysupdate`, the data partition via `systemd-repart`, the five boot values from A-04 as credentials.

## Rationale

1. **This stops CRIU from deciding the base.** With Fedora CoreOS and Flatcar the kernel is fixed: if an option is missing you lose the checkpoint rung from R-C and can do nothing about it. With mkosi the kernel configuration is a file — the measurement from A-06 then changes one line instead of an architecture. A decision that depends on a measurement not yet taken is not a decision; that is the real reason for this choice.
2. **The security pipeline stays with Fedora** — exactly the argument with which A-01 rejects a distribution of one's own. CRIU is available there as a package, and so are cgroup v2, PSI, Landlock, btrfs and a current systemd.
3. **A-03 through A-05 describe systemd's own image scheme point by point.** mkosi is its build tool. With rpm-ostree and Zincati, FCOS brings a second, competing update model that works against the channel discipline and the boot counter from A-03.
4. **Reproducible through a package snapshot held fixed.** Without pinning there is no bit-identical rebuild, and without that half the rationale from A-01 falls.
5. **No toolchain in the image** is a package list with mkosi, not rework — with a general distribution it is dismantling.

## Overturned by

a lasting need for a kernel of one's own and two people in the house who already know Nix. Then NixOS — the learning curve is the only reason it does not stand here.
