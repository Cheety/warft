# E-06 — Models

**Status:** ruled · **Source:** panel E-06 of the architecture overview, revision 2 (`workpod-plattform-leitstand.html`), carried over per AP-0.1. Translated under [the language ruling](language.md); the identifiers are untouched.

## Ruling

Three model roles, two independent providers, resolution through a capability statement instead of through a name in code. The checker never runs at the provider of the worker. The provider is pinned per project.

## Rationale

1. **The job names capabilities and a pinned version, not a provider** — the same resolution as with the requirement hash in T-03. Provider and key are inserted by the egress proxy (T-04). Switching provider is therefore a table row and not an intervention in prompts or code.
2. **The provider pinned per project,** because otherwise the prompt prefix cache expires on every switch — at this pool size the largest single item (G-03).
3. **The classifier is chosen to be self-operable.** It carries the volume; that way the platform is not unable to act during a provider disruption but slower and more expensive — and the third row of B-04 becomes executable instead of hypothetical.
4. **Budgets run in tokens, the euro cap is reserved at the most expensive permissible provider** (V-04). Then a fallback per B-04 never blows a cap, and nobody has to do arithmetic during an incident.
5. **That is why no provider name stands in this document.** The provider and price table changes monthly; names in the design become names in code, and code outlives prices.

## Overturned by

Nothing about the rule. the table is filled in at commissioning and maintained thereafter — it is configuration, not design.
